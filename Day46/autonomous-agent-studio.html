06 · What each agent does & how the stop-check governs the loop

Planner

Reads the spec once and produces an architecture plan: modules, functions, data flow, edge cases to cover. Runs once, before the loop.

Executor

Writes the first full working draft from the plan. Runs once — every draft after this is produced by the Improver, not the Executor.

Evaluator

Scores the current draft 0–10 against a balanced rubric (correctness, quality, robustness) every single round, live. Its score is the only thing the stop-check reads.

Critic

Only runs when the round is continuing. Turns the Evaluator's score into concrete, actionable fixes for the Improver.

Memory Manager

Distills what's been learned across rounds (recurring mistakes, decisions already made) into a short running memory, so the Improver doesn't re-litigate settled issues.

Improver

Takes draft + evaluation + critique + memory and produces the next full draft. Its output becomes next round's Evaluator input — this is the loop's return edge.

Safety Monitor

Runs once, only after a stop condition fires. Scans the final draft for unsafe patterns before it's shown as done.

Final Reviewer

Runs last. Takes the whole round history plus the safety scan and produces the polished deliverable and a plain-language summary of the run.

The stop-check runs immediately after every Evaluator call, in a fixed priority order: (1) plateau — score improved by less than the plateau delta for two consecutive rounds; (2) threshold — score has crossed the target; (3) hard cap — a safety net only, not the intended ending. Whichever fires first ends the loop and routes to Safety Monitor → Final Reviewer instead of back to Critic.

Architecture overview

Every box in the diagram above is a real, separate call to POST /v1/messages with its own system prompt and the accumulated state (spec, plan, current draft, evaluation history, memory) passed as context. There is no fixed round count in the code — the while loop keeps calling Evaluator → Critic → Memory Manager → Improver and re-checking the stop conditions until one trips, or the hard cap is hit as a safety net.

State threading: each round's Improver prompt includes the prior score, the Critic's fix list, and the Memory Manager's distilled notes — not just the raw draft — so quality compounds instead of resetting each pass.

Extension ideas
  • Add a parallel Test Writer agent that generates unit tests each round and feeds pass/fail counts into the Evaluator's rubric.
  • Let the Planner re-run mid-loop if the Critic repeatedly flags an architectural issue (a "replan" branch).
  • Persist memory across separate runs (localStorage/back-end) so the agent gets better at a *type* of task over time, not just within one run.
  • Add a human-in-the-loop checkpoint: pause after N rounds and let a person approve continuing vs. accepting the current draft.
  • Swap the domain: point the same Planner→Executor→Evaluator/Critic/Improver loop at prose, SQL queries, or API design instead of JS.
Further prompts for building more advanced autonomous systems
"Add a Test Writer agent that runs generated code in a sandboxed eval and reports real pass/fail counts to the Evaluator."
"Give the Planner the ability to trigger a full re-plan if the Critic flags the same structural issue two rounds running."
"Turn the Memory Manager's output into a persistent, cross-session knowledge base keyed by task type."
"Add a human-approval gate: pause the loop after the threshold is first approached and let the user accept or push for one more round."
"Replace the single Improver with two competing Improvers and have the Evaluator pick the stronger draft each round."
