How this was built

The system prompt

Every message — coaching turns and the final grade — is sent to the Claude API with one fixed system prompt that defines two modes: a conversational coaching mode (ask one focused follow‑up at a time, never invent data, keep it to 2–5 sentences) and a strict JSON grading mode that only activates when the "Grade my story" button fires a special instruction. Keeping both modes in one prompt (rather than two separate assistants) means the grader always has the full conversation as its source of truth, so it can't score information the student never actually gave it.



      
Why the interface looks this way

      
The brief was a coach for students practicing data storytelling — closer to an English teacher marking up a draft than a chatbot. The manuscript‑and‑margin layout borrows from that: your conversation reads like a working draft on the left, and the coach's notes collect in a ruled margin on the right, exactly where a human editor's red pen would land. The circular seal and score bars use the same crimson accent as the margin annotations so the final grade feels like a continuation of the notes, not a separate "results screen."


      
Extending this

      
    
        
  • Tools: give the assistant a code‑execution or chart tool so it can sanity‑check a claimed statistic against the numbers the student pasted in.
    • 
        
  • Memory: persist past drafts (via the storage API) so a student can track score trends across multiple stories over a term.
    • 
        
  • Multi‑step flows: split grading into two calls — a private "critique" pass and a separate "rewrite" pass — so the rewrite can react to the critique instead of being generated in parallel.
